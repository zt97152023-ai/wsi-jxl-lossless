# 写作入口与研究简报

本目录用于在不同机器上继续写作，不包含虚构的论文结果或未确定的作者信息。主张表为 [claims.csv](claims.csv)，原始证据仍在仓库 `results/`，不复制出多个版本。

## 研究问题

能否利用 JPEG 编码病理 WSI 的跨图块冗余、量化系数颜色相关性与局部条件，在保留**整个原始 SVS 文件全部字节**的同时，减少已有 JPEG XL 重压缩路径的存储成本？

表达矩阵使用用户已有 [Shared count codec](https://github.com/zt97152023-ai/shared-st-count-codec)，该方法不属于本仓库的改动或已验证联合实验。坐标与表达矩阵没有和本 WSI 方法完成统一容器的端到端验证，不能写成整套空间转录组平台已经完成。

## 建议正文结构

1. **问题与契约**：已压缩 SVS 的再压缩；明确 JPEG 原始码流与整文件恢复，不能混用无损像素压缩比。
2. **基础归档**：SVS 字节分区、共享 JPEG 表处理、JXL 重压缩、分组外层压缩与随机访问。
3. **可逆系数路径**：模板、逐频率颜色预测、DC 条件、布局和固定点残差；解释所有解码所需信息如何入包。
4. **实验**：先完整 CMU-1，再同源裁剪的容器实验，再两张切片的抽样算子比较；明确对应分母和强基线。
5. **消融与负结果**：颜色解释修复、过强正则的事后对照、三通道取舍、稀疏概率诊断与实际码长之间的区别。
6. **限制**：同厂商 RGB Q30、非跨中心验证、计算与读取成本、未支持网格的回退、自定义容器兼容性。

## 可主张与不可主张

主张表中的 `ALLOW_SCOPED` 仅允许在给定样本和配置下报告测量；`EXPLORATORY_ONLY` 必须写成开发/事后结果。表中百分比由指定 JSON 字段计算，相关证据有哈希。

以下主张当前没有足够证据：病理领域首创或 SOTA；跨患者/跨中心泛化；新算子将完整大切片进一步压过 99,009,379 B；稳定吞吐加速比；原生 OpenSlide 支持 `.wjxl`；核心 libjxl 熵编码器已重写；整套空间转录组矩阵/坐标/WSI 已统一验证。

当前两个大文件来自同源 Aperio RGB Q30，Small-Region 是 CMU-1 裁剪。图块数量不能替代独立切片/患者数量。原 JPEG 首次压缩前的信息无法由本方法恢复。
